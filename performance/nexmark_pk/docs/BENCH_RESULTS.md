### 观测与备注

1. **q2/q8 CPU 0/0 是测量缺陷，不是引擎空闲**（两查询 EPS 26.3M/25.2M，活跃窗仅 ~0.4s，
   在采样器首个 cputime 差分前烧完——基线前置修复前，见 `TEST_PLAN.md` §3）。其余查询 CPU
   与 EPS 负相关合理（重查询 avg 400%+）。**基线修复后需重跑 q2/q8 补记。**
2. **max 稳定 ~950% 而 `cores=8`**：实际可用核 ≥10（疑似 cgroup/亲和性把 nproc 限到 8 但引擎
   未受限），`cores=` 标称与实际不符，读 CPU 时按 max ~9.5 核理解。
3. **q6/q13 哨兵晚到**（各出现一次 `ingest: ack_lag=190/198` 进度行，未超时）：q6 滑窗
   10m avg 收口慢（EPS 371k，耗 ~48s）；q13 双规则链中间窗（EPS 312k，~46s）。
4. **RSS 峰值**：q13 9,021MB（bid_mod 中间窗 over=2d 全保留，已知语义代价）；q18 6,526MB；
   其余 2.5~3.7GB。evict 全 0。
5. **EPS 参照**（白皮书 OSS Flink 基线见 `OSS_VVR_BASELINE.md`）：q1 13M / q2 26M / q3 20M /
   q4 7.6M，量级均高于 OSS Flink 对应档（1.7M / 1.9M / 1.2M / 0.18M）。
6. **早期跑批**（同日 22:48，CPU 旧口径 1s 全生命周期，EPS/RSS 仍有效）：q1 13.06M/2,665MB、
   q2 26.34M/2,575MB、q3 20.52M/2,676MB、q4 7.52M/3,548MB——与本次一致（±8% 相位内）。
